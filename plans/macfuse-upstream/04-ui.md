Status: [ ] not started

## Goal

On macOS the Finder UI reflects the stock-macFUSE states from layer 02 and never installs a driver. The states are NotInstalled, Outdated, NeedsKextApproval, Ready (unmounted) and Enabled (mounted) (D17, D18). It links to https://macfuse.io (D9) and shows nothing unless the user goes looking for Finder access (D6). The consent checkbox goes (D13). The enable path keeps `installFuse` and its exit code 5 (D31). The kext popup becomes macFUSE approval help for the user's architecture only (D18, D35). Settings uses a `Kb.Switch` on macOS (D36), and turning it off unmounts with no confirm dialog (D43). Settings › Advanced gets an "Install command line tool" button (D39). The installer's helper exit codes and their critical-update badge go (D38). Windows (Dokan) and Linux behave exactly as today (D4).

## Acceptance criteria

- With macFUSE absent, nothing mentions macFUSE until the user opens the Files banner, the Finder icon popup or Settings › Files. The banner can be dismissed and stays dismissed (D6).
